# 交互规范手册

（用户 2026-10-23 要求留的手册。作者：）

以后**每加一样能摆在世界里的东西**，都要照这里检查一遍。这些规矩都来自用户实际玩出来的问题。

---

## 1. 鼠标中键复制：对着哪样就复制哪样

**规矩**：创造模式下按中键，要复制准星对着的那一样东西本身，连同它里面装的东西，不能复制成它下面、它旁边或者把它装在里面的方块。

| 情况 | 应该复制出 | 现在怎么做到的 |
|---|---|---|
| 桌上的盘子 | 那个盘子，连盘里的菜 | `PlateHolderBlock.getPickStack` 按准星找盘子，`Placed.toItem()` 把菜放进盘子物品里 |
| 桌上的饮料、碗、蘸料碗 | 那瓶饮料 / 那只碗本身 | 同上（`Placed.self`） |
| 灶台上的锅 | 锅 | `StoveBlock.getPickStack`：`aimsAtPot` 就给锅；高灶台上半截 `StoveTopBlock` 转给灶台 |
| 灶台的灶身 | 灶台 | 同上 |
| 砧板上的肉 / 土豆 | 那样东西 | `CuttingBoardBlock.getPickStack`：准星高过板面就是板上的东西 |
| 蘸料台上半截（看不见的那格） | 蘸料台 | `SauceStationTopBlock.getPickStack` |

**做法**：在方块的 `getPickStack` 里用 `PlateHolderBlock.pickPlayer`（客户端填的「当前玩家」）找准星位置，判断对着哪一样。

**最容易漏的坑：东西不在自己那一格里**
- 矮火锅桌上的盘子、饮料，底面比自己那一格低 5 像素，沉进了下面桌子那一格。
- 原版准星一格一格查方块，查到桌子那一格只认桌子，于是对着盘子下半截选中的是桌子，中键复制出来也是桌子。这就是用户报的「桌上的饮料、菜复制不了」。
- `TallReach`（由 `EntityRaycastMixin` 调用）专门补这件事。每查一格时，它会多看两样：
  - 下面那格**伸上来**的部分：高桌子、高灶台、蘸料台；
  - 上面那格**垂下来**的部分：矮桌上的盘子。
- **新东西只要形状超出自己那一格（低于 0 或高于 16 像素），不用另写代码，但一定要进游戏试中键和右键。**

## 2. 选中框：只框准星对着的那一样

**规矩**：一格里装着好几样独立东西时，黑色选中框只框准星对着的那一样，不能把这一格里的全框上。用户的原话是「选中的是对的，但指示器全都选上了，观感不好」。

| 方块 | 一格里有什么 | 框哪个 |
|---|---|---|
| 灶台 / 高灶台（含上半截） | 灶身 + 锅 | 对着锅框锅（连锅耳朵），对着灶身框灶身 |
| 盘子格 | 好几个盘子 / 饮料 / 碗 | 只框对着的那个，盘里有菜时连菜的高度一起框 |
| 砧板 | 砧板 + 板上的东西 | 对着东西框东西，否则框砧板 |
| 蘸料台（含头顶那格） | 9 个小碗 + 台阶 | 对着哪个碗框哪个碗，对着台阶框台阶 |

**做法**：
- 方块实现 `PartOutline.aimedPart(...)`，返回对着的那一部分的形状；返回 `null` 表示照原版框整个。
- `client/PartOutlineRenderer` 在画选中框时接管：只画这一部分，颜色和粗细同原版。

**注意**：
- `getOutlineShape` 仍然要返回**整个**形状，因为准星就是靠它判断点没点中。选中框画哪一部分，只在 `aimedPart` 里决定。
- 形状会随方块实体变化的（比如板上有没有东西），方块设置里要加 `dynamicBounds()`，否则原版缓存形状会出错（以前「踩盘子抽搐」就是这样）。

## 3. 新东西的检查清单

每加一样能摆在世界里的东西，进游戏逐条试：

1. **中键**：对着它复制，得到的是它本身，连同里面的东西。
2. **选中框**：一格里有几样东西时，只框对着的那样。
3. **右键 / 挖**：对着哪样就操作哪样，比如对着锅挖只挖锅。
4. **超出一格**：从侧面、上面、下面各个角度去点超出的那部分，准星要选中它，不能穿过去选到后面或下面的方块。
5. **改了 ID**：
   - **alpha 阶段（用户 2026-10-24）**：不管旧存档，名字对不上就直接改——物品 / 方块 ID、代码里的常量、方块状态取值、模型和贴图文件名、语言键一起改；旧 ID 兼容（`LegacyIds`）已经删了。
   - 出了 alpha、玩家有正式存档以后，改已发布的 ID 要先问用户，需要的话再做旧 ID 兼容（以前的做法：注册表查找时把旧 ID 换成新 ID）。
6. **网页查看器**：
   - 方块实体渲染器、界面都要同步改 `viewer/animations.js`、`viewer/screens.js`。
   - 新物品要在 `viewer/categories.json` 里有分类关键词，不能掉进「其他」。
7. **方块实体同步**：东西拿空了、清零了，写进去的数据也不能整个为空。原版客户端收到空数据会直接跳过，画面停在上一个样子（0.1.2-alpha 砧板的肉浆就是这样）。至少写一个固定字段。
8. **会用到「代码画」模型（builtin/entity）的物品**：模型里要写 `particle` 贴图。拿它吃东西、挖方块时会掉碎屑，没有贴图就显示紫黑格子。
9. **能放进去加工的东西要有白名单**：锅、砧板这类「放东西进去变成别的」的方块，只收该收的东西（锅只收食物，照烟熏炉）。不要直接套熔炉配方，否则木头、矿石也能塞进去（0.1.2-alpha 的锅就这样）。
