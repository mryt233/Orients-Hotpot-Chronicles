# 数值配置说明

作者：mryt233，2026-10-29 建。主工程「之晗的火锅物语」第一版；配方类的数值不在本文范围内。

## 不用改代码怎么调数值

1. 进一次单人世界（或启动一次服务器），模组会在游戏目录下生成配置：

   ```
   config/orients_hotpot_chronicles.json
   ```

   开发环境分别在 `mod/fabric/run-server/config/`、`mod/neoforge/run-server/config/`（客户端为对应 `run-client/config/`）。

2. 打开改数字，保存。
3. 生效方式：

   | 改的是 | 怎么生效 |
   |---|---|
   | 这个文件里的全部内容（食物、汤底、燃料、蘸料、烹饪） | 游戏里执行 `/orientshotpot reload`（需要管理员权限），立即生效，**不用重启游戏** |
   | 配方里的烧炼时间、烧炼经验、合成比例 | 不在这个文件里，在数据包 `recipe/*.json`，改完 `/reload` 就行 |
   | 粒子强度、或者不想手改 JSON | 在游戏里打开可视化设置界面点「保存并生效」，立即生效（见下面「游戏内设置界面」） |

   食物的饥饿值是在**吃东西的那一刻**才按配置算的，所以也能热重载。

| `drink` | `orient_cola.amplifier` | 之晗可乐每口速度、急迫的等级（共用），0 = I 级 | 0 | 0～9 整数 |

| `soup_bowl` | `<汤底>.amplifier` | 主效果的等级，0 = I 级 | 0 | 0～9 整数 |

| `soup_bowl` | `<汤底>.second_amplifier` | 副效果的等级，0 = I 级 | 0 | 0～9 整数 |
| `soup_bowl` | `<汤底>.fire_duration` | 红汤「抗火」持续多久（tick）；0 = 不加（特辣起生效，变态辣自动翻倍） | 红汤 300，其余 0 | 0～100000 整数 |
| `soup_bowl` | `<汤底>.fire_amplifier` | 红汤「抗火」的等级（只有红汤用） | 0 | 0～9 整数 |
| `soup_bowl` | `<汤底>.hunger_duration` | 红汤负面「饥饿」持续多久（tick）；0 = 不加（特辣起生效，变态辣再顺延） | 红汤 120，其余 0 | 0～100000 整数 |
| `soup_bowl` | `<汤底>.hunger_amplifier` | 红汤负面「饥饿」的等级（只有红汤用） | 0 | 0～9 整数 |
| `cooking` | `fallback_ticks` | 没有烹饪配方的食材在锅里煮多久 | 200 | 0～100000 整数 |
| `cooking` | `fallback_xp` | 这类食材出锅给多少经验 | 0.15 | 0～100 |
| `cooking` | `xp_per_item` | 按份计算经验时的兜底值 | 0.7 | 0～100 |
| `cooking` | `tofu_cook_ticks` | 整块冷豆腐在锅里煮成热豆腐要多久 | 200 | 1～100000 整数 |
| `cooking` | `tofu_overcook_ticks` | 豆腐从下锅到煮过头（碎成热豆腐块）的总时长，含煮熟那段，要大于 `tofu_cook_ticks` | 600 | 1～100000 整数 |
| `cooking` | `items.<生食材 ID>` | 这种生食材在锅里煮多久才算熟（tick）；写进这里就不用去改数据包熔炉配方 | 各种食材不同，见下面「涮煮时间」 | 1～100000 整数 |
| `client` | `particle_intensity` | 火锅的热气、灶口火苗和火星子的浓淡百分比；0 = 全部关掉。**只读本机这一份配置**，联机时不跟着服务器走 | 100 | 0～100 整数 |

20 tick = 1 秒。饥饿值 2 点 = 饥饿条上 1 个完整图标，原版上限仍是 20，写更大的数字不会扩大饥饿条。

### 涮煮时间（`cooking.items`）

这些生食材的涮煮时间直接在配置里改，**不用去改数据包熔炉配方**；改完 `/orientshotpot reload` 立即生效。
mryt233 改（2026-11-10）：短键只作用于 `orients_hotpot_chronicles` 命名空间，第三方同名物品不会套用本模组的配置。火锅自己的登记食材以配置为准，原版 / 第三方食材照旧走烟熏炉、营火、熔炉配方，最后用 `cooking.fallback_ticks` 兜底。

配置重载和数据包 `/reload` 后，已经在锅里的生食材保留熟度比例，按新时间继续煮，剩余秒数随之更新。

| 分档 | 生食材 | 默认 |
|---|---|---|
| 极快熟 | `beef_loin_slice`（吊龙）、`tripe`（毛肚） | 50 tick（2.5 秒） |
| 快熟 | `fatty_beef_roll`、`mutton_roll`、`potato_slice`、`cold_tofu_cube`、`ham_sausage_slice`、`peeled_shrimp` | 100 tick（5 秒） |
| 中等 | `shrimp`（带壳虾）、`shrimp_paste`（虾滑）、`raw_ham_sausage`（生火腿肠） | 150 tick（7.5 秒） |
| 慢熟 | `beef_loin`（整块牛脊肉）、`beef_meatball`、`pork_meatball`、`mutton_meatball`、`fish_ball`、`cilantro_beef_meatball`、`cilantro_pork_meatball`、`cilantro_mutton_meatball`、`cilantro_fish_ball` | 200 tick（10 秒） |

整块冷豆腐 `cold_tofu` 不在这个表里：它走 `cooking.tofu_cook_ticks`（煮成热豆腐）和 `cooking.tofu_overcook_ticks`（煮过头碎掉）。

### 汤底风味效果对照（mryt233 改，2026-11-06，清单 #125）

`soup_bowl.<汤底>` 里的 `duration` / `amplifier` 和 `second_duration` / `second_amplifier` 分别对应下表的主效果和副效果，
红汤另有 `fire_*`（抗火）和 `hunger_*`（负面饥饿）两组。任何一项配成 0 或不写就不加对应效果。

| 汤底 | 主效果（`duration`） | 副效果（`second_duration`） | 说明 |
|---|---|---|---|
| `clear` 清汤 | 移动速度 I 15 秒 | 饱和 1 tick | 原汁原味、轻盈健步；喝下还解反胃 |
| `rich_stock` 高汤 | 抗性提升 I 15 秒 | 伤害吸收 I 30 秒 | 牛骨老鸡、坚韧滋补；**已无缓慢效果** |
| `mushroom` 菌汤 | 生命恢复 I 10 秒 | — | 山珍菌菇、活血养生 |
| `spicy` 红汤 | 力量（微辣 I 6 秒 → 变态辣 II 15 秒） | 速度（微辣 6 秒 → 变态辣 12 秒） | 麻辣浓烈、发汗驱寒；特辣起加 `fire_*` 抗火与 `hunger_*` 饥饿 |
| `tomato` 番茄汤 | 急迫 I 15 秒 | — | 酸甜浓郁、生津开胃；喝下还解反胃 |
| `three_fresh` 三鲜汤 | 水下呼吸 20 秒 | 幸运 I 30 秒 | 干贝海米、鲜掉眉毛 |

红汤的辣度档位在主效果上再叠：每升一档力量 +3 秒（中辣起力量等级再 +1）；速度在微辣 6 秒基础上，中辣 +3 秒（9 秒）、特辣 +4 秒（10 秒）、变态辣 +6 秒（12 秒）；特辣（2 档）起开始给抗火 15 秒，变态辣（3 档）抗火翻倍至 30 秒。饥饿同理，微辣、中辣不挨饿，特辣给 `hunger_duration`（默认 6 秒 = 120 tick），变态辣再多 2 秒（+40 tick，共 8 秒）。

**旧键自动改名**（mryt233 改，2026-11-04，r134b）：豆腐改了 ID，老配置里的 `food.tofu`（营养值）、`food.tofu_cube`、`food.cooked_tofu_cube` 会在启动、进服和 `/orientshotpot reload` 前自动改成 `food.cold_tofu`、`food.cold_tofu_cube`、`food.hot_tofu_cube`；开发版里短暂用过的 `food.tofu.cook_ticks` / `overcook_ticks` 挪到 `cooking.tofu_cook_ticks` / `cooking.tofu_overcook_ticks`。新名字下已经写了值时以新名字为准，旧键直接删掉。只在真有旧键时才改写文件（其他内容保留），日志里会有一行 `[hotpot] Renamed legacy config keys: ...`；文件写坏时不动它。

**汤碗的「缓慢」旧键自动清掉**（mryt233 改，2026-11-06，清单 #125）：高汤不再给缓慢，老的 `soup_bowl.<汤底>.slow_duration` / `slow_amplifier` 已经作废。升级后第一次读配置时会自动处理：老 `slow_duration` 的值搬进新的 `second_duration`（高汤老的 60 tick 会变成伤害吸收 3 秒，自己再按上表调），没有就删；两个旧键随后删掉，所以之后不会再报「不支持的配置项」警告。

## 游戏内设置界面

不想手改 JSON 的话，游戏里有可视化设置界面（2026-11-05 加，r135e）：

- **从火锅指南进**：拿「火锅指南」右键打开书，点书外框左下角的「⚙」小按钮。
- **从模组列表进**（NeoForge）：主菜单 →「模组」→ 选中「之晗的火锅物语」→「配置」按钮。
  Fabric 装 Mod Menu 时也能从模组列表进（NeoForge 用的是原生的 Config 入口）。

界面里四个页签：

| 页签 | 能改什么 |
|---|---|
| 特效与常规 | 火锅粒子强度滑块 0%～100%，另有「关闭 / 柔和 / 标准」三个快捷档；下面还有烹饪的兜底时间、经验、豆腐煮制时间与 6 种汤底的加热倍率 |
| 涮煮时间 | 本模组每种生食材的涮煮刻数，带 −20 / −5 / +5 / +20 快捷按钮，旁边显示折算的秒数 |
| 汤碗与调料 | 6 种汤碗的营养与效果（每种 10 项：营养、主效果、副效果、红汤的抗火 / 饥饿）、10 种蘸料的时长 / 等级 / 味精多回的饥饿值、饮料每口营养与每种饮料的效果 |
| 食物营养 | 全部 50 种食物的饥饿值与饱和度 |

底部三个按钮：

- **保存并生效**：把改动写回 `config/orients_hotpot_chronicles.json` 并立即重载，不用敲命令、不用重启；回执会报告警告条数；写盘失败会停在当前页，说明改动是否仅在本次游戏有效及失败原因。原配置写坏或超大时先备份为 `.json.broken-<时间>` 再保存，并显示备份名。单人游戏里食物营养、涮煮时间、汤底速度等当场生效。
- **恢复默认**：把所有项恢复成默认值（粒子强度回 100%），再点保存才写进文件。
- **取消**：这次改的数值都不要，粒子强度也恢复到打开界面之前的值。

粒子强度是**本机**设置：拖动滑块时立刻生效（不用保存也能看到变化），保存后会写进你自己这份配置文件的 `client.particle_intensity`。联机时它不会被服务器的数值覆盖。

## 写错了会怎样

| 情况 | 结果 |
|---|---|
| 删掉整个文件 | 全部用默认值，并重新生成一份完整的 |
| 删掉其中某一项 | 那一项用默认值，启动时自动补回 |
| 某一项不是数字 | 只回退这一项，启动日志和 `/orientshotpot reload` 里会说清楚是哪一项 |
| 某一项超出范围 | 同上，那一项回退默认值 |
| 键名写错（比如把 `hunger` 写成 `hungry`） | 警告「不支持的配置项 food.xxx.hungry，已忽略」，不会静默失效 |
| 整个文件写坏（少个逗号之类） | 全部用默认值，**原文件原样保留**方便你自己改，日志里有提示 |

## 多人服务器

只需要改**服务端**那一份。玩家进服时、以及管理员执行 `/orientshotpot reload` 时，服务端会把自己的数值同步给所有在线客户端，不用每位玩家复制文件；退出服务器后会清掉上一台的数值。

**例外**：`client.particle_intensity`（粒子强度）不进这个同步，永远只认玩家自己电脑上那份配置——每人机器性能不同，不该被服务器统一改掉。多人服里玩家自己在游戏内设置界面调的粒子强度，也只影响他自己的画面。

老版本客户端没有这个同步包时会被跳过，不会踢人——数值结算全在服务端，客户端拿不到也照常玩。

## 以后加新数值的规矩（开发者看）

加一个可调数值时，照这个流程：

1. 在代码里保留默认值，注册时用 `Config.rememberXxx(...)` 把它记进模板。
2. 取值时用 `Config.xxx(...)`，把默认值作为兜底参数传进去。
3. 在 `Config.fieldHelp()` 里补一行说明，写清范围和单位。
4. 现在所有配置项都支持 `/orientshotpot reload` 热重载。以后如果加了必须在物品注册时就固定、运行时改不了的值，要在说明里写明「必须重启游戏」。
5. 更新本文的表格。

三条兜底规则（缺文件生成、缺项回退、坏文件保留）不要绕过，`Config.read()` 已经统一处理了。
