# 数值配置说明

作者：mryt233，2026-10-29 建。主工程「之晗的火锅物语」第一版；配方类的数值不在本文范围内。

## 不用改代码怎么调数值

1. 进一次单人世界（或启动一次服务器），模组会在游戏目录下生成配置：

   ```
   config/orients_hotpot_chronicles.json
   ```

   开发环境是 `mod/run/config/orients_hotpot_chronicles.json`。

2. 打开改数字，保存。
3. 生效方式：

   | 改的是 | 怎么生效 |
   |---|---|
   | 这个文件里的全部内容（食物、汤底、燃料、蘸料、烹饪） | 游戏里执行 `/orientshotpot reload`（需要管理员权限），立即生效，**不用重启游戏** |
   | 配方里的烧炼时间、烧炼经验、合成比例 | 不在这个文件里，在数据包 `recipe/*.json`，改完 `/reload` 就行 |

   食物的饥饿值是在**吃东西的那一刻**才按配置算的，所以也能热重载。

## 可调的项

| 分组 | 键 | 意思 | 默认 | 允许范围 |
|---|---|---|---|---|
| `food` | `<物品 ID>.hunger` | 回多少饥饿值 | 各物品不同 | 0～100 整数 |
| `food` | `<物品 ID>.saturation` | 饱和度系数（不是直接加的点数） | 各物品不同 | 0～10 |
| `soup_speed` | `clear` / `rich_stock` / `mushroom` / `spicy` / `tomato` / `three_fresh` | 锅的加热速度倍率 | 1.0 / 0.85 / 1.15 / 1.3 / 1.1 / 1.0 | 0～10 |
| `fuel` | `<燃料>.power` | 加热功率倍率 | 0.65 / 1.0 / 1.6 | 0～10 |
| `fuel` | `<燃料>.burn_ticks` | 一份燃料能烧多久（tick） | 300 / 1600 / 20000 | 0～100000 整数 |
| `seasoning` | `<蘸料>.duration` | 状态效果持续多久（tick）；0 = 不加效果 | 各蘸料不同 | 0～100000 整数 |
| `seasoning` | `<蘸料>.amplifier` | 效果等级，0 = I 级 | 0 | 0～9 整数 |
| `seasoning` | `msg.hunger` | 味精多回几点饥饿值 | 2 | 0～100 整数 |
| `drink` | `sip.hunger` | 饮料瓶 / 一杯饮料每喝一口回多少饥饿值（一杯水、一杯牛奶不回） | 2 | 0～100 整数 |
| `drink` | `sip.saturation` | 饮料每口的饱和度系数 | 0.3 | 0～10 |
| `cooking` | `fallback_ticks` | 没有烹饪配方的食材在锅里煮多久 | 200 | 0～100000 整数 |
| `cooking` | `fallback_xp` | 这类食材出锅给多少经验 | 0.15 | 0～100 |
| `cooking` | `xp_per_item` | 按份计算经验时的兜底值 | 0.7 | 0～100 |

20 tick = 1 秒。饥饿值 2 点 = 饥饿条上 1 个完整图标，原版上限仍是 20，写更大的数字不会扩大饥饿条。

## 写错了会怎样

| 情况 | 结果 |
|---|---|
| 删掉整个文件 | 全部用默认值，并重新生成一份完整的 |
| 删掉其中某一项 | 那一项用默认值，启动时自动补回 |
| 某一项不是数字 | 只回退这一项，启动日志和 `/orientshotpot reload` 里会说清楚是哪一项 |
| 某一项超出范围 | 同上，那一项回退默认值 |
| 键名写错（比如把 `hunger` 写成 `hungry`） | 警告「不支持的配置项 food.xxx.hungry，已忽略」，不会静默失效 |
| 整个文件写坏（少个逗号之类） | 全部用默认值，**原文件原样保留**方便你自己改，日志里有提示 |

## 多人服务器

只需要改**服务端**那一份。玩家进服时、以及管理员执行 `/orientshotpot reload` 时，服务端会把自己的数值同步给所有在线客户端，不用每位玩家复制文件；退出服务器后会清掉上一台的数值。

老版本客户端没有这个同步包时会被跳过，不会踢人——数值结算全在服务端，客户端拿不到也照常玩。

## 以后加新数值的规矩（开发者看）

加一个可调数值时，照这个流程：

1. 在代码里保留默认值，注册时用 `Config.rememberXxx(...)` 把它记进模板。
2. 取值时用 `Config.xxx(...)`，把默认值作为兜底参数传进去。
3. 在 `Config.fieldHelp()` 里补一行说明，写清范围和单位。
4. 现在所有配置项都支持 `/orientshotpot reload` 热重载。以后如果加了必须在物品注册时就固定、运行时改不了的值，要在说明里写明「必须重启游戏」。
5. 更新本文的表格。

三条兜底规则（缺文件生成、缺项回退、坏文件保留）不要绕过，`Config.read()` 已经统一处理了。
