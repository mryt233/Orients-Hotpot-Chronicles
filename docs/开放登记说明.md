# 开放登记与数据包配方说明

作者：mryt233　日期：2026-11-13　对应开发版：r148（第四批 4F-1～4F-3）

本文说明第三方内容或整合包 / 数据包如何向「之晗的火锅物语」登记或覆盖**汤底**与**蘸料**，以及多处来源同时存在时的优先级规则。

---

## 1. 数据包配方（纯 JSON，`/reload` 生效）

### 1.1 目录与登记 ID 约定

为避免与合成配方的 ID（例如 `recipe/oyster_sauce.json`）撞名，汤底与蘸料配方必须放在规定子目录下，载入时**剥掉第一级目录前缀**作为登记 ID：

| 配方类型 (`type`) | 文件路径 | 配方 ID | 实际登记 ID |
| --- | --- | --- | --- |
| `orients_hotpot_chronicles:soup_base` | `data/<ns>/recipe/soup/<name>.json` | `<ns>:soup/<name>` | `<ns>:<name>` |
| `orients_hotpot_chronicles:seasoning` | `data/<ns>/recipe/seasoning/<name>.json` | `<ns>:seasoning/<name>` | `<ns>:<name>` |

- 未放在 `recipe/soup/` 或 `recipe/seasoning/` 子目录下的对应类型配方将被跳过并记录警告日志。
- 若登记 ID 与内置项（如 `orients_hotpot_chronicles:clear`、`orients_hotpot_chronicles:chili_oil`）或 Java 扩展项相同，则对**写出的字段做部分覆盖**，未写字段保留原定义；否则作为新增项按完整 ID 字典序排在内置项之后。
- **已知范围与 4F-3 渲染 / 汤碗策略**：
  - 纯 JSON 数据包不会新增独立物品 / 贴图 / 语言文件；客户端通过原版配方同步包自动收到全部条目，两个配方类型均声明 `isSpecial = true`，不进入原版配方书。
  - **通用汤碗（4F-3）**：已注册专属 `SoupBowlItem` 的内置与子模组汤底优先盛出专属汤碗；未注册专属碗物品的新增汤底（含纯 JSON 数据包汤底）在盛汤时统一产出通用汤碗 `orients_hotpot_chronicles:soup_bowl`，通过 `orients_hotpot_chronicles:soup` 物品组件保存完整汤底 ID（红汤类同时携带 `spicy_level` 组件）。
  - **`other` 方块状态与汤面渲染（4F-3）**：内置 6 种汤底沿用各自 `SoupVisual` 方块状态；所有非内置新增汤底在方块状态层面统一走 `SoupVisual.OTHER`（`soup=other`）。渲染时，子模组可按汤底 ID 提供自定义贴图 `assets/<ns>/textures/block/hot_pot_top_<path>.png` 与 `assets/<ns>/textures/block/hot_pot_top_<path>_boiling.png`；纯 JSON 数据包无自定义贴图时，按 `screen_colors.base` / `bubble_colors.body` 着色渲染清汤基底与沸腾气泡。
  - **未知 / 已卸载汤底兼容**：卸载子模组或移除数据包后，锅存档、通用汤碗与桌面碗方块保留原汤底 ID 与组件数据不覆盖，界面、提示与汤面显示未知占位，重新装回后自动恢复。

### 1.2 `orients_hotpot_chronicles:soup_base` 字段参考

覆盖内置项时仅写需要修改的字段；新增汤底时至少必须提供 `source` 或 `additive` 之一。颜色字段支持整数或 `"#RRGGBB"` / `"#AARRGGBB"` / `"0xAARRGGBB"` 字符串。

```json
{
  "type": "orients_hotpot_chronicles:soup_base",
  "source": "minecraft:mushroom_stew",
  "remainder": "minecraft:bowl",
  "speed_multiplier": 1.35,
  "clears_nausea": true,
  "spicy": false,
  "bowl_food": {
    "hunger": 6,
    "saturation": 0.8
  },
  "main_effect": {
    "id": "minecraft:regeneration",
    "duration": 200
  },
  "second_effect": {
    "id": "minecraft:saturation",
    "duration": 20
  },
  "lang_key": "text.mypack.soup.herbal",
  "screen_colors": {
    "base": "#FFD9C7A3",
    "hi": "#FFF1E5C9",
    "lo": "#FFB8A37D",
    "bits": ["#FF8C7A5B", "#FFE6D6B8"]
  },
  "bubble_colors": {
    "body": "#FFF3EAD6",
    "hi": "#FFFFFFFF"
  }
}
```

- 可选字段：`source`（物品 ID）、`remainder`（倒汤返还容器，默认 `minecraft:air`）、`additive`（锅底料物品 ID，仅对清汤生效）、`speed_multiplier`（`0.1..10.0`）、`bowl_food`（`hunger` `0..100`、`saturation` `0.0..10.0`）、`main_effect` / `second_effect` / `fire_effect` / `hunger_effect`（`{ "id": "<effect>", "duration": 0..100000 }`）、`clears_nausea`、`spicy`、`lang_key`、`bowl_id`（仅作配方数据元数据保留，当前版本不参与选碗也不创建新碗；纯数据包新增汤底统一使用通用汤碗 `orients_hotpot_chronicles:soup_bowl`，仅内置或 Java 侧通过 `SoupBowlItem` 登记的汤底使用专属碗）、`screen_colors`、`bubble_colors`。

### 1.3 `orients_hotpot_chronicles:seasoning` 字段参考

新增蘸料时必须提供 `raws`；覆盖内置项时可仅写需要修改的字段。`raws` 支持单个物品字符串或物品字符串数组。

```json
{
  "type": "orients_hotpot_chronicles:seasoning",
  "raws": ["minecraft:amethyst_shard"],
  "color": "#FF7CB342",
  "effect": {
    "id": "minecraft:haste",
    "duration": 240,
    "amplifier": 1
  },
  "hunger": 2,
  "removes": ["minecraft:hunger"],
  "garnish": true,
  "name_key": "text.mypack.seasoning.wasabi",
  "effect_key": "text.mypack.seasoning.wasabi.effect"
}
```

- 可选字段：`raws`（字符串或数组）、`color`（整型或十六进制字符串）、`effect`（`{ "id": "<effect>", "duration": 0..100000, "amplifier": 0..9 }`）、`hunger`（`0..100`）、`removes`（可清除的效果 ID 数组）、`garnish`（布尔，决定点状撒料尺寸）、`name_key`、`effect_key`。

## 2. 优先级规则（配置文件 > 数据包 > 代码默认值）

同一项内置数值同时存在于 `config/orients_hotpot_chronicles.json`、数据包和代码默认值时：

1. **配置文件显式修改**优先：当配置中对应键存在且数值**不等于模板默认值**时，采用配置值（`/orientshotpot reload` 或设置界面保存即时生效）。
2. **数据包配方**次之：当配置中该键仍为自动生成的模板默认值（或未配置）时，数据包中的修改直接生效。
3. **代码默认值**兜底。
4. **隔离原则**：第三方 Java 子模组和纯 JSON 数据包新增的异命名空间条目**不写入** `config/orients_hotpot_chronicles.json`，也不受本模组内置同名路径配置键（例如 `soup_speed.clear`）影响；其数值由自身定义或数据包控制。

## 3. Java 启动期开放登记（子模组）

- **依赖声明**：子模组须同时声明依赖本模组与对应版本的 `orient_framework` 前置框架，否则启动期会由加载器或运行期报缺。
  - Fabric（`fabric.mod.json`）：`"depends": { "orients_hotpot_chronicles": ">=1.0.0-r148", "orient_framework": ">=0.2.0 <0.3.0" }`
  - NeoForge（`META-INF/neoforge.mods.toml`）：声明两条 `[[dependencies.<modId>]]`（`modId="orients_hotpot_chronicles"`、`versionRange="[1.0.0-r148,)"`；以及 `modId="orient_framework"`、`versionRange="[0.2.0,0.3.0)"`，`ordering="AFTER"`）。
- **冻结窗口**：子模组应在服务端启动冻结（`HotPotHooks.freezeRegistries()`，Fabric `SERVER_STARTING` / NeoForge `ServerStartingEvent`）之前完成登记，冻结后再登记会抛出 `IllegalStateException`；重复 ID 会抛出 `IllegalArgumentException`。
- **汤底登记**：使用 `SoupDef.builder(ResourceLocation)` 构造后调用 `Soups.register(SoupDef)`。若子模组需要专属汤碗物品，在物品注册阶段使用 `new SoupBowlItem(ResourceLocation soupId)` 注册即可（支持先于 `Soups.register` 完成，使用时延迟解析）。
- **蘸料登记**：使用 `SeasoningDef.builder(ResourceLocation)`（原料通过 `Supplier<Item>` 延迟提供）构造后调用 `Seasonings.register(SeasoningDef)`。
- **桌面物件与自定义渲染**：桌面方块可直接实现 `TableBlock` 或继承 `PlateBlock`，外部 / 原版物品实现 `TableItem` 并调用 `TableObjects.registerItem(Item, TableItem)` 接入火锅桌上桌与交互；客户端如需自定义整件绘制或叠加层，使用 `TableBlockRenderers.registerBlock(PlateBlock, BlockRenderer)` 或 `TableBlockRenderers.registerOverlay(Item, SelfOverlayRenderer)`。
- **旧版存档与缺失兼容**：汤底与蘸料存档及物品组件自 4D/4E 起持久化完整 ID；卸载子模组或移除数据包后，存档与 `orients_hotpot_chronicles:soup` 组件保留原 ID 并在界面/提示/汤面中显示未知占位，重新装回后自动恢复。
- **完整可运行示例工程**：见 `experiments/hotpot-submod-sample/`（双端独立子模组工程，演示 `SoupDef`、`SeasoningDef`、`SoupBowlItem` 与 `TableItem` + `TableObjects.registerItem`）。

## 4. `content/materials.json` 事实来源口径

- `mod/content/materials.json` **仅作为本模组内置材质与内置 6 种汤底静态资源生成器的唯一事实来源**（用于生成随模组发布的静态方块状态、模型、贴图及 `check_content.py` 校验清单）。
- 第三方子模组（Java 启动期登记）与纯 JSON 数据包（`/reload` 动态配方）均在运行期通过 `Soups` / `Seasonings` 登记表与配方系统动态接入，**不改动 `materials.json`**，也无需为新增汤底或蘸料重跑静态生成器。
